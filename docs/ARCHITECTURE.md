# 架构与维护

网页内容及共用计算来自原项目。已移除 Vinext 服务端、D1/R2、ChatGPT 登录和 Sites 发布配置。Vite 构建的 React 资源随 APK 安装，视图调用本地 repository，不访问原网站。

`local-api.ts` 是视图适配边界。`/api/expenses` 等字符串只是本地操作键，不会产生 HTTP 请求。只有 `public-data.ts` 对外请求公开数据，主机被明确限定。

## 持久化

安卓社区 SQLite 插件创建 `sfo_travel` 数据库。`local_data(key, value)` 保存版本化文档及缓存；`personal:v1` 是账目和收藏的单个原子快照。串行队列和单条 UPSERT 避免并发丢失或部分更新。限 10,000 笔账目及 10,000 个收藏，适用于个人差旅规模。

照片保存在 `Directory.Data/receipts/`，数据库仅保存引用。写账目失败清理新照片；删除数据库记录后清理照片。异常中断或删除失败可能留下不可见的孤立文件，不会让已删除记录重现。照片压至最长边 1,800 像素并转 JPEG。

浏览器预览使用 IndexedDB，localStorage 只存界面偏好。安卓 SQLite 初始化失败展示错误，绝不自动清空或降级成临时存储。

缓存按来源独立保存。没有缓存且离线时天气显示不可用；有旧预报时保留日期和过期提示。历史汇率和会议快照标记过期状态，未知时区会议不自动换算。

## 备份

JSON 和照片用 AES-GCM 加密。每份备份随机生成 16-byte salt、12-byte IV，以 PBKDF2-SHA256 210,000 次迭代派生密钥；密码不保存。

恢复先校验数据、金额、日期、图片引用，再写入。已有 ID 保留本机版本，新图片生成独立路径，数据库一次提交，失败清理新文件。CSV 不包含完整照片，不能作为恢复备份。

schema 升级必须实现显式迁移并补旧数据夹具测试，禁止用空数据覆盖旧格式。正式包名和签名保持稳定，以便 Android 升级保留应用目录。

## 测试边界

单元测试覆盖存储协议、并发、校验、加密及回滚。Playwright 使用手机视口和离线公共服务检查照片、账目、重启、恢复和偏好。它们不替代真机 SQLite 插件、Camera、分享面板和 WebView 测试。

真机发布检查：离线新增照片账目 → 强制停止 → 再打开 → 备份到外部文件夹 → 导入并检查照片 → 同签名升级 → 确认数据仍在。还应检查返回键、字体放大、拍照取消和储存不足。
